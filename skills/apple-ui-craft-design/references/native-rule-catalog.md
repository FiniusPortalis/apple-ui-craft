# Native Apple UI rule catalog

**Scope:** iOS, iPadOS, macOS  
**Rule/source check:** 2026-10-17 (Apple page bodies and exact section anchors; see [verification notes](source-verification.md)).

These rules turn broad HIG guidance into reviewable decisions. They do not create a mechanical compliance score. Severity depends on user impact, evidence, task frequency, reversibility, and platform context.

## Rule notation

- `Required` means a high-confidence failure is normally actionable before release.
- `Expected` means deviation needs a product-specific reason and validation.
- `Advisory` means use judgment; do not label it a violation.
- These levels are this skill's review priorities, not Apple certification or a verbatim Apple requirement scale. Preserve the qualifications in the linked source.
- Each rule links to the exact Apple section plus a short paraphrased paragraph locator. Open those sections before using the rule.
- `APPLE-HIG` denotes the cited recommendation; exceptions and concrete acceptance checks remain contextual. Links marked as background support a synthesis or product heuristic, not an Apple mandate.
- A successful link/anchor check proves source reachability only. Re-read the passage, platform scope, and API availability before claiming current guidance.
- Verification dates cover the mapped rules, not every example or API in this package. See [source policy](source-policy.md) for unavailable-source handling.

## Severity is impact-based

Do not map `Required` mechanically to `Blocker`. Examples:

- A gesture-only “Delete account” path that excludes keyboard and VoiceOver can be a `Blocker`.
- A 40×40 pt custom iPad control with adequate spacing may be `Minor` or `Investigation`, not automatically `Major`.
- A toolbar-only macOS command can be `Major` if it blocks keyboard/menu access, but `Minor` if an equivalent menu command already exists elsewhere.
- A screenshot that appears to clip text is an `EVIDENCE-GAP` until the runtime layout or code confirms it.
